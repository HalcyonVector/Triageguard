\section*{Introduction}

This literature survey examines twenty works, all published from 2021 onward, spanning every pillar
TriageGuard integrates. Papers 1 to 10 (2024 onward, journal-first with one review paper) cover AI-assisted
memory forensics, entropy- and header-based ransomware detection, measured cryptographic benchmarks for symmetric
and asymmetric ciphers (AES, DES, 3DES, RSA, ElGamal, ECC), RSA weak-key cryptanalysis, JWT/OAuth 2.0 token
security, and LLM robustness against adversarial input. Papers 11 to 20 (2021 to 2024) add memory-based malware
detection, LLMs in digital forensics, recovering ransomware and TLS keys from memory, identifying cryptographic
primitives in binaries, ransomware's use of hybrid encryption, fast shared-prime detection for RSA, and the
prompt-injection attacks and defences our red-team track tests. Table~\ref{tab:litsurvey} illustrates each
paper's domain, methodology, and key findings alongside its reported cryptographic parameters (key size,
plaintext/ciphertext size, encryption type, timing, and performance) where applicable, its limitations, and how
it relates to three specific pillars of TriageGuard: memory forensics, cryptographic stress analysis, and AI
robustness.

\vspace{0.5cm}
\noindent This table illustrates that real, measured cryptographic parameters exist for symmetric ciphers (Paper~1),
asymmetric ciphers under realistic file loads (Paper~2), weak RSA configurations (Papers~3 and 17), and JWT/OAuth
token security under production-like conditions (Papers~4 and 5), and that keys and cipher implementations can be
recovered from memory and binaries (Papers~13 to 15). AI-assisted memory forensics (Papers~6, 7, 11, 12),
entropy/header-based ransomware detection (Papers~8, 10, 16), and LLM robustness against adversarial input
(Papers~9, 18 to 20) are each addressed independently elsewhere. No single existing work reports all of these side
by side or feeds them into one automated, evidence-cited triage report, and the LLM-based forensic tools
(Papers~6, 7, 12) never test what happens when the evidence itself carries injected instructions, which Paper~18
shows is realistic. TriageGuard's contribution is to operationalise these benchmarked thresholds, key sizes and
detection techniques into a single pipeline that flags a sample's actual cryptographic and authentication risk,
rather than just its presence, while also red-teaming and hardening its own AI reporting layer.
